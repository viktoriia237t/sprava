# Справа — каталог сервісів для малого бізнесу в Україні

Тестове завдання на вакансію Junior AI Web Developer.

## План сайту

Мета, аудиторія, сторінки та структура — у [PLAN.md](PLAN.md).

## Як використано FreeSerp

| Де | Індекс і параметри | Коли виконується |
|---|---|---|
| Дані кожного сервісу: Domain Rating, заголовок головної, AI-опис, технологія | `index=sites`, `q=<домен>`, `all=1` | під час збірки, вбудовується в статику |
| «Схожі сайти в Україні» на сторінці сервісу (конкуренти) | `index=sites`, `tld=ua`, `sort=dr&order=desc` + фільтр за словами в заголовку і стоп-словами (казино, кредити, новини) | під час збірки |
| «Згадки в мережі» на сторінці сервісу | `index=web`, `lang=uk` | під час збірки |
| «Не знайшли потрібне?» | `index=web`, `lang=uk` | у браузері (див. примітку про CORS) |
| Наповнення каталогу | `sort=dr` за категоріями: так знайдено NovaPay, Smart Kasa, EDIN, SMARTFIN, Sitniks, Nomis, Фонд розвитку підприємництва замість сервісів, яких немає в індексі | під час розробки |

**Примітка про CORS.** FreeSerp надсилає заголовок `Access-Control-Allow-Origin: *` двічі, і браузери відкидають таку відповідь (`The 'Access-Control-Allow-Origin' header contains multiple values '*, *'`). Тому все, що можна, сайт бере під час збірки, на сервері, де CORS не діє. Живий пошук спершу пробує запит напряму, а якщо браузер його заблокує, показує кнопку «Відкрити результати на freeserp.ai» з тим самим запитом. Щойно FreeSerp виправить заголовок, пошук запрацює на сайті без змін у коді.

Якщо FreeSerp не зміг прочитати головну сторінку (заглушка, «Access Denied», лише CSS), сайт не показує сміттєвий опис, а чесно пише про це. Якщо API недоступний під час збірки, сайт однаково збирається з редакційними описами. GitHub Actions перезбирає сайт щопонеділка, щоб дані FreeSerp були свіжими.

## Технології

Nuxt 4 (Vue 3, TypeScript) зі статичною генерацією (`nuxt generate`): під час збірки кожна сторінка рендериться в готовий HTML, а дані FreeSerp потрапляють у `_payload.json`. Тому сайт швидко відкривається, індексується пошуковиками і хоститься на GitHub Pages без сервера. Шрифти Unbounded і Manrope з Google Fonts, обидва з кирилицею. Є темна тема, адаптивна верстка, доступність з клавіатури, обробка помилок і порожніх станів.

```
shared/
  catalog.ts              редакційна частина: категорії, сервіси, маршрути
  freeserp.ts             типи даних FreeSerp
server/api/catalog.get.ts запити до FreeSerp Main під час збірки
app/
  app.vue                 шапка, футер, тост
  pages/index.vue         маршрут, каталог, пошук, мій набір
  pages/service/[id].vue  сторінка сервісу
  components/             ServiceRow, KitButton, SerpResults
  composables/            useCatalogData, useKit (localStorage), useToast
  utils/freeserp.ts       клієнт FreeSerp Global для браузера
```

## Як я працював з AI

1. Попросив AI проаналізувати умови тестового і запропонувати кілька ідей різних типів. Обрав каталог, бо він дає реальну користь і дозволяє використати API.
2. AI вивчив документацію FreeSerp (параметри, поля, застереження щодо `went_live` і `dr`) і перевірив реальні відповіді обох індексів.
3. AI перевірив кожен домен каталогу в FreeSerp Main: 7 сервісів там не знайшлося, тож за допомогою `sort=dr` за категоріями AI підібрав заміни, а я їх затвердив.
4. AI склав дизайн-систему (палітра, шрифти, сітка), написав першу версію на чистому JS, потім за моїм завданням переписав її на Nuxt зі статичною генерацією.
5. Автоматичні добірки AI спершу показали шум (казино, магазини дитячих конструкторів, новинні портали), тому ми додали фільтри і перевірили результат по кожній категорії.
6. Під час тестування в браузері AI знайшов, що FreeSerp дублює CORS-заголовок, тому згадки перенесено на етап збірки, а для живого пошуку додано запасний варіант.
7. Перевірено: збірка, перевірка типів (`nuxt typecheck`), базовий шлях для GitHub Pages і 39 автоматизованих сценаріїв у headless Chromium: маршрут і його збереження, набір (додавання, копіювання, очищення, збереження між сторінками), пошук, фільтри, чипи, сортування за DR, порожній стан, сторінки сервісів, 404, керування з клавіатури, темна тема, екран телефона 375 px без горизонтального скролу.

## Запуск і деплой

```bash
npm install
npm run dev        # розробка: http://localhost:3000
npm run generate   # статика в .output/public
```

GitHub Pages: у репозиторії Settings → Pages → Source: **GitHub Actions**. Після кожного push у `main` (і щопонеділка) workflow `.github/workflows/deploy.yml` збирає сайт і публікує його на `https://<user>.github.io/<repo>/`.

## Що можна додати далі

- Порівняння двох-трьох сервісів поруч.
- Блок «Нові сервіси» через FreeSerp (`sort=went_live`). Поки не додано: `went_live` — це дата, коли FreeSerp вперше побачив сайт, а не дата запуску, тож без ручної перевірки блок вводив би в оману.
- Відгуки користувачів і рейтинг.
